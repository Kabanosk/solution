## What was done
- `backend/cfo/channels/base.py`: `Notifier` protocol (runtime-checkable): `send_dm(employee, text, level, actions=()) -> str` (opaque message ref `"<channel>:<ts>"`, for `ApprovalRequest.channel_ref`), `on_approval(handler)`, `on_chat(handler)`, `start()`, `stop()`. Models: `Action` (+`ActionKind`, helper `approval_actions(request_id)`), `ApprovalAnswer(request_id, approved, employee_id, message_ref)`, `ChatMessage(employee_id, text, message_ref)`, `ChatReply(text, level)`. `Level = PolicyLevel | "SIMULATED"` (`SIMULATED` is a label, not a policy level; constant `SIMULATED`). Handlers are sync callables; a chat handler may return `str` (labelled AUTO), `ChatReply`, or `None` (silent).
- `backend/cfo/channels/slack.py`: `SlackNotifier(employees, bot_token, app_token, client=None, user_map=None, process_before_response=False, socket_handler_factory=SocketModeHandler)` and `SlackNotifier.from_settings(employees)`. Block Kit message `*[LEVEL]* text` (text escaped, so `<!channel>` cannot fire; fallback text also starts with `[LEVEL]`), Approve/Reject buttons (`cfo_approve` / `cfo_reject`, value = request id). Click: ack, call handler, then replace buttons by "Approved/Rejected by <name>"; if the handler raises, buttons stay and the user gets a generic ephemeral error. DMs and `app_mention` from known employees go to the chat handler and the reply is posted (in thread for mentions); bots, edits, non-DM messages ignored; strangers get a labelled refusal and are never routed; unknown clickers are ignored.
- Employee mapping: `Employee.slack_user_id`, overridden by `SLACK_USER_MAP=vincenzo=U01,grazyna=U02` (new `slack_user_map` setting in `config.py`, `.env.example`).
- `slack-bolt>=1.20` added to `backend/pyproject.toml` / `uv.lock` (bolt 1.30.0).
- `deploy/slack-app-manifest.yaml` (scopes chat:write, im:write, im:history, users:read, app_mentions:read; events message.im, app_mention; Socket Mode and interactivity on; Messages tab writable) and `docs/slack-setup.md` (workspace, app from manifest, `SLACK_BOT_TOKEN` = Bot User OAuth Token xoxb, `SLACK_APP_TOKEN` = app-level token xapp with `connections:write`, finding user ids, mapping, smoke test, troubleshooting).

## Tested and did not work
- First version let Bolt authorize itself: it builds a per-request `WebClient` and calls the real `auth.test` (network, `invalid_auth`). Fixed with a custom `authorize` closure that calls `auth.test` once through the injected client. A bound method does not work as `authorize` (Bolt matches arguments by name, "multiple values for argument 'self'").
- Test events must use `type: event_callback` (the Socket Mode inner payload), not `events_api`.
- Not tested: a real Slack workspace and the real websocket (needs T013 tokens). The manifest has not been imported into Slack yet.
