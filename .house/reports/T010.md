# T010: December event simulator with speed control

- **Agent / model:** coder / sonnet

## Goal
Replay `data/generated/events/december.jsonl` into Postgres at `SIM_SPEED`, with start / pause / step / jump control from the CLI and from plain functions: `.house/tasks/T010-simulator.md`.

## What was done
New package `backend/cfo/sim/`:
- `engine.py`: `Simulator(repo, events, speed, clock, subscribers)`. Events are sorted by `ts`; each is written with `cfo.data.load.apply_event` (so transactions, invoices and cost metrics land in the domain tables too) and then handed to the subscribers. The agent is never called; T011 registers `Agent.handle` via `cfo.sim.subscribe(cb)` (process-wide) or passes `subscribers=[...]`. A failing subscriber is logged and does not stop the clock. Dispatch happens after the DB lock is released, so callbacks may call the control functions.
- State in table `sim_state` (single row: sim_time, paused, speed, last_tick, next_index), created by the simulator itself (`CREATE TABLE IF NOT EXISTS`), so `schema.sql` is untouched. API, CLI and worker share it. An advisory lock (session level, survives commits) serialises processes that advance the replay, so no event is emitted twice.
- Clock: injectable `clock()` (epoch seconds); sim time advances by `(real elapsed) * speed` only on `tick()` and only while running. `run(stop, wait=...)` is the worker loop: tick, then wait until the next event is due (max 1 s). Initial speed from `SIM_SPEED`, changed by `start(speed=...)` / `set_speed`. Sim time starts at 2025-12-01 00:00 UTC, paused. When the last event is emitted the simulator pauses itself (`finished`); sim time is never run past the last event.
- Control: `start(speed?)`, `pause()` (events due up to the pause are emitted first), `step()` (emit the next event now, sim time jumps to its `ts`, clock state unchanged), `jump(date|datetime|"YYYY-MM-DD")` (to 00:00 UTC of that day, emits everything in between; backwards raises `ValueError`), `reset()` (back to start, paused; does not clear the events table, use `cfo.data.load --reset`), `status()` -> `SimStatus` (live sim_time, paused, speed, emitted, total, next_event_ts, finished).
- `control.py`: plain module functions for the API (T020): `start, pause, step, jump, reset, status`, each on its own connection, events from `data/generated` (or `data_dir`). Note: events written by `step`/`jump` go to the subscribers of the calling process.
- CLI: `python -m cfo.sim start [--speed N] [--run] | pause | step | jump YYYY-MM-DD | status | reset | run`. `start` only flips the shared state; the clock runs while a worker executes `run` (or `start --run`).
