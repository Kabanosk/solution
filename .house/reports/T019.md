# T019: API read endpoints wired to the database

- **Agent / model:** coder / sonnet
- **Branch / commits:** task/T019-api-read (routers + services, tests, docs; main merged in without conflicts before the final check)
- **Date:** 2026-11-20 18:45

## Goal
Replace the T018 stubs with database-backed data for `/v1/kpis`, `/v1/costs/by-team`, `/v1/cost-metrics`, `/v1/decisions`, `/v1/rules` and (added in the brief, T015 is merged) `/v1/forecast/liquidity`, with the D-013 safety buffer as a field (`.house/tasks/T019-api-read.md`).

## What was done
- `cfo/api/deps.py`: `get_repo` (one `Repository` per request; tests use `app.dependency_overrides[get_repo]`).
- New `cfo/api/services.py` holds all read logic; the six routers are thin and no longer use `mark_stub` (`stub: false`, no `X-Stub` header; `stubs.py` stays only as reference values for `test_cost_metrics`).
  - `/v1/kpis`: balance = running sum of all bookings, `as_of` = last booking day, 30-day change, average monthly in/outflows over whole calendar months (a running month is left out), undocumented payments = `list_transactions(undocumented_only=True)`, pending approvals = `approval_requests.status='pending'`, `open_cost_alerts` = series whose last point has an anomaly (T007), forecast summary from T015.
  - `/v1/costs/by-team`: T014 `monthly_cost_by_team` + teams table; extra team `company` for tax / social security (no owner, no budget); default range = first booking month .. last booking day.
  - `/v1/cost-metrics`: `to_api_series(load_series(repo))`, `kind` filter.
  - `/v1/decisions` (filters, newest first, count + page in SQL), `/v1/decisions/{id}`, `/v1/rules` (active filter, newest first).
  - `/v1/forecast/liquidity`: `liquidity_forecast(days, model=...)` from T015. Model is memory-cached, loaded from `FORECAST_MODEL_PATH` / `models/liquidity_xgb.json`, trained on the first request and saved when the file is missing (lock-protected). Weekly sampling and "trough is never sampled away" kept from the stub.
- **Shape changes (documented in `docs/api.md`, `docs/openapi.json` regenerated), all additive or semantic:**
  - `LiquidityForecast.safety_buffer` (Money, new): default = largest monthly fixed cost (payroll, rent, tax, social security, utilities) = 17,730.00 EUR on the seeded year, same definition as T016; `SAFETY_BUFFER_EUR` overrides.
  - `ForecastSummary.safety_buffer` and `first_below_buffer_date` (new, nullable).
  - **Semantics:** `gaps` are now stretches below the safety buffer (D-013), not below zero; `first_negative_date` is literally the first day below zero (null on real data). `lowest_point`/`lowest_balance` is the lowest of the whole horizon, which on real data is right after `as_of` (June is a local dip, not the minimum).
  - Interval `lower`/`upper` is an approximation (1.28 x holdout RMSE x sqrt(days ahead)); `model.version` = `trained-until-<date>`, `trained_at` = model file mtime.
  - New error envelopes: 503 `database_unavailable` (psycopg OperationalError) and 503 `no_data` (empty DB).
- `tests/test_api_skeleton.py`: stub-value tests removed (moved to `test_api_read.py` with real data); validation, error model, CORS, OpenAPI tests kept with a dummy repo override; added 500 and 503 envelope tests.
- `tests/test_api_read.py` (26 tests): isolated schemas `t019_nov` (statement as delivered) and `t019_dec` (December replay applied), dropped afterwards; skips when Postgres or `data/generated` is missing; model stored in a temp dir.

Real balance as of 2025-12-31 is 32,945.51, not 42,338.93. The front should not hard-code the stub values.
