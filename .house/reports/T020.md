## What was done
- `cfo/api/routers/approvals.py`: `GET /v1/approvals` (`state` = pending|resolved|approved|rejected, limit/offset, newest first), `GET /v1/approvals/{id}` (embeds the decision), `POST /v1/approvals/{id}:approve|reject` with body `{"by"}`. Calls `Agent.resume_approval`; `KeyError` -> 404, `PermissionError` -> 403 `forbidden`, a repeated identical answer -> 200 with `already_resolved: true` (agent is idempotent), the opposite answer after resolution -> 409 `conflict`. Response = approval state + `already_resolved`.
- Agent comes from the FastAPI dependency `cfo.api.deps.get_agent` (module registry `set_agent(agent)`, to be called by the process that builds the agent, T011; 503 `agent_unavailable` when none). Tests override the dependency.
- `cfo/api/stream.py` + `routers/events.py`: `GET /v1/events` SSE with `decision`, `approval` and `event` messages. One cursor per table (events carry simulated time, decisions the wall clock), the SSE `id:` is the whole cursor, so `Last-Event-ID` (or `?last_event_id=`) resumes exactly; no header = start from now. Approvals are re-emitted when answered (key `COALESCE(resolved_at, created_at)`) with the resolved decision. Keepalive comments. The generator is a plain sync generator; poll interval, `wait`, repo factory and `max_polls` come from the injectable `StreamConfig` dependency, so tests never sleep.
- `routers/sim.py`: `GET /v1/sim`, `POST /v1/sim:start` (optional `{speed}`), `:pause`, `:step` through the `get_sim_control` dependency (default adapts `cfo.sim.control`). `jump`/`reset` not exposed.
- Schemas appended to `schemas.py`; `docs/api.md` has shapes, curl examples, the SSE message table and the T010 caveat (subscribers live in the worker process: `start`/`pause` only flip shared state, `step` dispatches to the API process's subscribers); `docs/openapi.json` regenerated.
