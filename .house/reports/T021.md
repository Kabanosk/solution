## Goal
`Containerfile` for the backend: UBI 9 Python 3.12, uv, non-root, OpenShift arbitrary UID friendly, entrypoints for API, worker and the three MCP servers (D-008): `.house/tasks/T021-containerfile.md`.

## What was done
- `Containerfile` (repo root): base `registry.access.redhat.com/ubi9/python-312`, `uv` via pip, `uv sync --frozen --no-dev --no-editable` from `backend/uv.lock` into `/opt/venv` (deps layer first, then the code, so rebuilds are cached). `HOME=/app`; `/app` and `/opt/venv` are `chgrp 0` + `g=u`; runs as `USER 1001`. `EXPOSE 8000 8001 8002 8003`. `ENTRYPOINT ["cfo"]`, `CMD ["api"]`.
- `deploy/cfo-entrypoint.sh` (installed as `/usr/local/bin/cfo`), the dispatcher:
  - `cfo api` (default): `uvicorn cfo.api.app:app --host 0.0.0.0 --port ${API_PORT:-8000}`
  - `cfo mcp <company-db|workstations|hr> [port]`: streamable HTTP on 8001 / 8002 / 8003 (endpoint `/mcp`)
  - `cfo worker`: `python -m cfo.run` (T011's entrypoint; does not exist on main yet)
  - `cfo migrate|generate|load [args]`: `cfo.db.migrate`, `cfo.data.generate`, `cfo.data.load`
  - anything else is exec'd as is (`cfo python -m cfo.sim ...`, `cfo sh`).
- `.containerignore` and identical `.dockerignore`: `.git .house .worktrees .claude .idea .env* data/generated challenge models .venv __pycache__ docs` etc.
- I did not touch `pyproject.toml`, so there is no conflict with T010/T015.

## Evidence
- `docker build -f Containerfile -t cfo-backend:test .` succeeded (image 2.14 GB; heavy deps from langgraph/pandas/uvicorn[standard]).
- `docker run -d -p 18000:8000 cfo-backend:test`, then `curl --retry 10 --retry-connrefused` on `/healthz`: `HTTP/1.1 200 {"status":"ok","version":"0.1.0"}`; container ran as `uid=1001 gid=0`; container removed afterwards.
