## What was done
- `deploy/openshift/app/` with its own `kustomization.yaml`; the root `deploy/kustomization.yaml` got only `openshift/app` added to `resources` (after merging T022 it reads `[postgres.yaml, files.yaml, openshift/db, openshift/app]`; the one conflict was resolved by keeping both).
- `imagestream.yaml` + `buildconfig.yaml`: Docker strategy, `https://github.com/Kabanosk/solution` `main`, `dockerfilePath: Containerfile` (the root `Dockerfile` is the file server), output `cfo-backend:latest`.
- `api.yaml` (Deployment, Service, edge TLS Route with http->https redirect, `/healthz` probes), `worker.yaml` (`cfo worker`, no Service), `mcp.yaml` (`mcp-company-db` 8001, `mcp-workstations` 8002, `mcp-hr` 8003; TCP probes; internal only).
- `configmap.yaml` `cfo-config`: `LLM_BASE_URL` / `LLM_MODEL` obvious `CHANGE-ME-...` placeholders, `MCP_*_URL`, `SIM_SPEED`, `CORS_ORIGINS`. Used via `envFrom` by all pods.
- Secrets: no templates with values; `README.md` documents `oc create secret generic cfo-secrets --from-literal=SLACK_BOT_TOKEN/SLACK_APP_TOKEN/LLM_API_KEY`. The worker reads it through an `optional` secretRef, so pods start without it.
- `DATABASE_URL` is composed in each pod from keys `POSTGRESQL_USER/PASSWORD/DATABASE` of Secret `postgres` using `$(VAR)` expansion (the three vars precede `DATABASE_URL`).
- `pvc.yaml`: `cfo-data` 1Gi RWO, mounted read-only at `/app/data` by `mcp-workstations` (`WORKSTATIONS_ROOT=/app/data/generated/workstations`, `strategy: Recreate`); T022's seed Job already references the same claim.
- Deployments use `image-registry.openshift-image-registry.svc:5000/cfo-agent-uwur/cfo-backend:latest` plus an `image.openshift.io/triggers` annotation, so a build rolls them out. Requests are small (api 100m/384Mi, worker 100m/256Mi, MCP 50m/128Mi).
- `deploy/openshift/app/README.md` (first deploy, LLM endpoint, secrets) and the status rows of `INFRA.md`.
