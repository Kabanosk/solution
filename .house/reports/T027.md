## Goal
Every agent run is one MLflow trace with node, sub-agent and LLM spans: `.house/tasks/T027-agent-tracing.md` (D-015).

## What was done
- New `backend/cfo/observability.py`:
  - `init_tracing(settings=None) -> bool`: no-op (and no `mlflow` import) unless `MLFLOW_TRACKING_URI` is set and
    `mlflow` is importable. Otherwise `set_tracking_uri`, `set_experiment(MLFLOW_AGENT_EXPERIMENT, default cfo-agent)`,
    `mlflow.openai.autolog()`. Idempotent, never raises (warning + returns False).
  - `span(...)`, `set_trace_tags(...)`, `traced_node(name, fn)`, `traced_llm(llm)`, `enabled()`, `reset_tracing()`
    (tests). All are pass-throughs while tracing is off; every MLflow call is guarded (one warning, agent continues).
  - `MLFLOW_*` variables are read from the process environment only, not `.env` (same rule T026 documented in
    INFRA.md). No auth is set in code; MLflow reads `MLFLOW_TRACKING_AUTH` etc. itself.
- `backend/cfo/agent/graph.py` (small edits): `Agent.handle` is the root span `agent.handle`, `resume_approval` the
  root span `agent.resume_approval` (old bodies moved to `_handle` / `_resume_approval` unchanged); nodes are
  registered through `obs.traced_node`; `Deps.llm` is wrapped with `obs.traced_llm`. Trace tags:
  `cfo.event_kind`, `cfo.event_id`, `cfo.transaction_id`, `cfo.policy_level` (highest level among the decisions of
  the run: APPROVAL > NOTIFY > AUTO, `NONE` without a decision), `cfo.outcome` (`HandleResult.status`),
  `cfo.simulated` (yes/no), `cfo.actions`; for resume also `cfo.approval_id`, `cfo.approved`.
- `backend/cfo/agent/investigate.py`: sub-agent nodes are spans `investigate.gather|detect|explain` under the
  `investigate` node span.
- LLM calls: span `llm.chat` (type CHAT_MODEL, inputs = messages/tool names, outputs = parsed response) under the
  node that made the call. Works for any `LLM` (FakeLLM too); with the real client the `openai` autolog span
  (tokens, wire payload) nests inside it.
- A LangGraph interrupt (`await_approval`) closes its span as OK with attribute `cfo.interrupted`, not as an error.
- `backend/cfo/api/app.py`: `init_tracing()` in the FastAPI lifespan (runs at server start, not at import).
- `backend/pyproject.toml`: extra `mlflow>=3` (same line as T026; lock resolves 3.18.0). `INFRA.md` §5 and
  `.env.example`: `MLFLOW_AGENT_EXPERIMENT`. `.gitignore`: `mlruns/`, `mlflow.db`.

**For T011 / `cfo.run`:** call `from cfo.observability import init_tracing; init_tracing()` once at the start of the
worker entrypoint, before `build_agent`/the first event. When this branch was last merged with main, `cfo/run.py`
was not on main yet, so that call is not wired. The API process already calls it (lifespan), which covers the
agent-in-API mode.

## Tested and did not work
- `mlflow.langchain.autolog()` together with explicit node spans: every node appears twice (`LangGraph -> a -> a`).
  Tried on a two-node graph. I kept the explicit spans (they work without LangChain callbacks and let the
  interrupt be a non-error) and did not enable the LangChain autolog.
- First `house check` was RED: 2 failed / 2 errors in the agent tests of `test_tracing.py`, while the same tests
  passed alone. Most likely cause (not proven): they shared the Postgres schema `t005_test` of `test_agent.py` with
  another run on the same database. The tracing tests now use a schema of their own (`t027_test_<pid>`); GREEN
  twice since. `test_agent.py` itself still uses one fixed schema, so two worktrees running it at once can collide.
- MLflow with a sqlite store writes trace artifacts to `./mlruns` in the cwd; the tests now create the experiment
  with an artifact location in `tmp_path`.
