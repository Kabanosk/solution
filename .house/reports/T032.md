# T032: LLM usage and cost estimation from vLLM metrics (API)

- **Agent / model:** coder / sonnet
- **Branch / commits:** task/T032-llm-usage-cost (feature, docs + openapi, merge of main)
- **Date:** 2026-11-20 22:00

## Goal
Estimate and expose what the agent costs on the cluster: per-call attribution, vLLM Prometheus sampling, a cost model with assumptions, and `GET /v1/llm/usage` and `/v1/llm/usage/live`: `.house/tasks/T032-llm-usage-cost.md` (D-016).

## What was done
- `cfo/usage/` (new package): `recorder.py` (context variable `usage_context(event_id, event_type, purpose, decision_id)`, `record_call`, `DbSink` with a short connect timeout and a 30 s circuit breaker, injectable sink and clocks), `vllm_metrics.py` (Prometheus text parser, counter-reset arithmetic, histogram quantile), `store.py` (SQL), `sampler.py` + `__main__.py` (`python -m cfo.usage sample --every 60 | --once`; `start_background()` for the worker; stop via `Event.wait`, no sleeps), `cost.py` (pure Decimal math), `report.py` (report and live snapshot), `settings.py` (own settings class, so `config.py` is not touched by the usage settings).
- `cfo/llm.py` (additive): `TokenUsage`, `LLMResponse.usage`, timing and `record_call` in `OpenAICompatLLM.chat` (also on failure, `success=false`) and `FakeLLM.chat` (model `fake`). Missing `usage` from the server: heuristic 4 characters per token, row flagged `estimated`. Recording swallows every error.
- Context: `Agent.handle` wraps the graph in `usage_context(event_id, event_type)` and afterwards links the event's calls to the decision it ended with (`link_decision`); `llm_tasks.py` / `policy.py` tag calls with `purpose` (`extract_invoice`, `alternative_queries`, `explain`, `parse_rule`). Verified that the context variable reaches LangGraph node threads (test).
- Schema (additive): `llm_usage`, `vllm_metrics_samples` (counters, per-finish-reason split, cached prompt tokens, inference-time and e2e sums, histogram buckets as JSONB, gauges).
- API: `routers/llm_usage.py`, `schemas_usage.py`; `docs/api.md` section with curl and example responses; `docs/openapi.json` regenerated; env docs in INFRA.md and `.env.example`.
- Cost model: busy-time (sum of request latency x rate, an upper bound), amortized (wall-clock window x rate x our token share from vLLM counter deltas; share 1.0 and flagged without samples), hosted list prices. Cluster block uses `request_inference_time_seconds` (e2e as fallback) for GPU time. Cost per action: LLM calls attributed to the last decision of the event; divided by all decisions of that action type in the range. Costs have six decimals (one documented exception to the two-decimal money rule).
- Merge of main: conflicts in `config.py`, `llm.py`, `.env.example` because main already had `LLM_VERIFY_TLS` / `tls_verify_setting` (same idea as the coordinator asked); took main's version, `uv lock` clean.

## Facts verified (assumptions, with source and date, also in code and the `assumptions` block)
- vLLM v1 metric names: `vllm:prompt_tokens_total`, `vllm:generation_tokens_total`, `vllm:request_success_total{finished_reason}`, `vllm:e2e_request_latency_seconds`, `vllm:num_requests_running|waiting`, `vllm:kv_cache_usage_perc`, label `model_name`: https://docs.vllm.ai/en/latest/design/metrics/ (read 2026-11-20). `gpu_cache_usage_perc` is the older name for the KV gauge, replaced by `kv_cache_usage_perc` (vLLM PR #18354 per https://github.com/vllm-project/aibrix/pull/1822, not confirmed in an official changelog); both are parsed, new wins. Confirmed against the REAL capture from the Granite pod (new name only).
- Metrics path and port: `/metrics` on the vLLM API port; Red Hat docs show 8000 for llm-d (https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.4/html/deploy_models_using_distributed_inference_with_llm-d/monitoring-llmd-deployments) and 8080 in some OpenShift AI serving runtime examples (https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/2.22/html-single/serving_models/index), so the port varies. On our cluster (coordinator, from Grzesiu): HTTPS, self-signed, port 8000.
- L4 price: AWS g6.xlarge (1x L4) USD 0.8048/h us-east-1, https://instances.vantage.sh/aws/ec2/g6.xlarge (aggregator, page does not show a snapshot date, read 2026-11-20); the Frankfurt price was not available (page fetch failed / region not shown). Default 0.70 EUR/h uses an assumed 0.87 EUR/USD. Not a quote.
- Hosted list prices (via OpenAI model pages, https://developers.openai.com/api/docs/models/gpt-5-mini and /gpt-5-nano, read 2026-11-20 through search results; direct page fetches failed with a DNS error): gpt-5-mini USD 0.25 in / 2.00 out, gpt-5-nano USD 0.05 / 0.40 per 1M tokens.

## Tested and did not work
- First draft compared the displayed (rounded) token share with exact math in a test and the heuristic prompt estimate ignored the message separator; both were test mistakes, fixed.

- Considered an LLM node name column; dropped, `purpose` plus event type carries the same information without touching every graph node.
