## Goal
Fix Slack findings 4, 21 and P3 of `reports/review-fixes.md` (`tasks/T043-fix-slack.md`).

## What was done
- **(4) Adapter type mismatch: already fixed by T011, test only.** `cfo/run.py` has `AgentNotifier`, which maps the
  agent's `send_dm(employee_id: str, ..., [ActionButton])` to `SlackNotifier.send_dm(Employee, ..., [Action])`
  via the repository. `SlackNotifier` itself keeps the channel-level `Employee` contract (`cfo.channels.base.Notifier`),
  so I did not change it. `test_slack_fixes.py` drives the real shape: `AgentNotifier(SlackNotifier, repo_factory)`
  called with an id string and `ActionButton(action_id="approve", ...)`, asserting the Slack blocks (buttons
  `cfo_approve`/`cfo_reject`, label `[APPROVAL]`) and that an unknown id raises `ValueError`, not `AttributeError`.
  These tests passed before any code change.
- **(21) app_mention answers public:** `_route_chat(..., private=True)` for mentions: the answer is DMed to the asker
  (post to the user id, no thread), the channel gets only an ephemeral "I answered you in a DM." visible to the asker.
  If the DM fails, the asker gets an ephemeral "could not send you a DM". Refusal to strangers and the generic
  error note still go to the channel thread (no data in them). Plain DM chat unchanged.
- **(P3) Labels:** every ephemeral error/refusal (`_ephemeral`) now starts with `[NOTIFY]`.
- **(P3) HR `slack_id`:** the seed parser does not read it (outside scope), so `docs/slack-setup.md` now says
  `SLACK_USER_MAP` is the supported path and the CSV column is ignored. Added a paragraph about private mention answers.
- Updated the old mention test in `test_slack.py` (it asserted the channel thread, which was the bug).
