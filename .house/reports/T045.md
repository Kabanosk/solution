## Goal
Findings 26 and the P3 forecast item of `reports/review-fixes.md` (Codex review of T014, T015, T016, T019). Task: `tasks/T045-fix-forecast-leakage.md`.

## What was done
Both findings were confirmed at HEAD before fixing.

1. **(26) Holdout leak, confirmed.** `train()` built `daily_features` from the full history (shutdown windows and due days inferred from all bookings), then split the table by rows. New `model.backtest_split(transactions, holdout_days, exclude_categories)` infers both from the bookings before the first holdout day, builds the features of train and test from that inference, and takes the targets from the real daily cash flow. `_backtest` uses it. The final model (the one saved, logged to MLflow, served) is still inferred from the full history, which is correct for production. The API interval (`api/services._sigma_daily`) reads `metrics["holdout_rmse"]`, so it uses the corrected value with no code change in `cfo/api`.
2. **(P3) Empty data, confirmed.**
   - `features.daily_features` returns an empty frame with the right columns and a DatetimeIndex when there are no bookings. Before: `NaT` ValueError from `pd.date_range`. `train` on no transactions still raises the clear "no transactions to train on".
   - `liquidity.forecast_with` gets an optional `buffer=`. Without fixed-cost rows and without a buffer it no longer fails: the forecast is built and `default_buffer` is left out of `attrs`. `review_liquidity` passes its `buffer` through, and with neither it raises the existing clear "pass buffer=" error from `_resolve_buffer`.
