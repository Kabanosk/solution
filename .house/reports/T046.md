## What was done
All findings were confirmed at HEAD first (T011/T032 had not touched them).

- **(22) Write token.** New `cfo/api/auth.py`: dependency `require_write_token` (HTTP bearer, `hmac.compare_digest`).
  `API_WRITE_TOKEN` unset/empty: everything stays open. Set: approve, reject, `sim:start|pause|step` return 401
  `unauthorized` (+ `WWW-Authenticate: Bearer`) without the right token, checked before body validation. Reads,
  `/healthz` and the SSE stream stay open. With a token, the body's `by` is ignored and the approval is answered as
  the CEO (`ApiSettings.ceo_id`, env `CEO_ID`, default `vincenzo`); the token holder gets 403 for approvals addressed
  to someone else. Slack approvals do not go through the API, untouched. OpenAPI declares the `WriteToken` scheme on
  the five write routes. Documented in `docs/api.md` ("Write protection") and `deploy/openshift/app/README.md`
  (the api already `envFrom`s Secret `slack` as optional, so the key goes there; no YAML change).
  The task says Secret `cfo-secrets`, but no manifest reads it; the token goes into `slack`.
- **(23) SSE.** `stream.stream` is an async generator; idle time is `await config.wait(...)` (default
  `asyncio.sleep`; a sync fake wait is still accepted so the old tests keep working), each poll runs in
  `asyncio.to_thread`. The route is `async def`. The first frame now carries `id:` (the connect cursor); an empty
  database encodes as `-` and decodes to an empty cursor (resume = everything that exists).
- **(P3)** 500 responses carry CORS headers (`errors.cors_headers`, mirrors the configured origins, because the
  server-error handler sits outside `CORSMiddleware`). 405 keeps `Allow` (the HTTP exception handler now forwards
  `exc.headers`). Date range validated after defaults (`from` after last booking, `to` before first booking): 422.
  A range over 120 months (`to=9999-12-31`, `from=0001-01-01`) is 422 instead of a 500. By-team costs no longer skip
  unlinked invoices when the statement is empty (the default range then follows those invoices; with bookings it
  stays as documented, booking range).
- `docs/openapi.json` regenerated with `python -m cfo.api.export_openapi docs/openapi.json` (there is no `openapi.json`
  at the repo root).
- Existing `test_api_approvals.py` adapted in 3 places: the first SSE frame now has an `id`, and the resume tests take
  tokens from data frames instead of "every frame with an id".
