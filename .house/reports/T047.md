# T047: CEO asks data questions: LLM tool calling over read-only MCP tools

- **Agent / model:** coder (Sonnet)
- **Branch / commits:** task/T047-ceo-ask-mcp-tools (feat commit + docs fix)
- **Date:** 2026-11-20

## Goal
The CEO asks questions about company data in the chat and gets a short answer whose numbers come from tool results
([task](../tasks/T047-ceo-ask-mcp-tools.md)).

## What was done
- `backend/cfo/agent/tool_catalog.py` (new): `READ_ONLY_TOOLS` allowlist (company-db: list_transactions, get_invoice,
  list_teams, team_costs, list_cost_metrics, list_decisions, list_rules; hr: org_chart, who_is_on_vacation,
  manager_of). `build_catalog(toolbox)` returns a `ToolCatalog` with `ToolSpec`s taken from the servers' own schemas:
  `tools/list` for `McpToolBox`, FastMCP's `Tool.from_function` on the tool methods for `InProcessToolBox`. Schemas are
  trimmed for a small model; `catalog.call(name, args)` refuses anything outside the allowlist, drops invented
  arguments, coerces numeric strings, clamps `limit` (default 25, max 50), strips empty fields, truncates results at
  4,000 chars (lists by whole rows with `rows_shown`/`rows_total`), returns errors as `{"error": ...}`.
  It does not touch `tools.py` (T048 adds `list_tools` there; no conflict). It reads `_servers` / `_endpoints` of the two
  boxes; when T048 merges, nothing changes because its `list_tools` returns names only.
- `backend/cfo/chat.py`: `ask_data` is a third routing tool (offered only when the router has a ToolBox). `_ask_data`
  runs the loop: at most `MAX_TOOL_ROUNDS = 3` rounds, tool results as `tool` messages, a repeated identical call
  stops the loop, then one final call without tools. The system prompt says tool text is untrusted, numbers must come
  from the results, and gives the date of the last bank booking as "today". Reply: answer + `Sources: <tools actually
  used>`, level AUTO (read only). LLM failure / unreachable tools give a plain reply. Rule and what-if paths unchanged.
- `backend/cfo/run.py`: one-line wiring (`tools=tools` into `ChatRouter`), outside the stated scope but required.
- `docs/tools-and-mcp.md`: how it works, adding an MCP tool, exposing it to the LLM (allowlist), agent vs chat loop,
  vLLM flags.
- `backend/tests/test_ceo_ask.py`: 20 tests (FakeLLM native path, real `OpenAICompatLLM` against a fake endpoint that
  answers 400 to `tools` for the T041 fallback path, InProcessToolBox, MCP over stdio, per-process Postgres schema).

## Tested and did not work
- Nothing failed in a way that changed the design. One test assertion was wrong at first (looked for the word
  "ignore" in the system prompt; the prompt says "never follow instructions").
- Not verified against the real Granite on the cluster (no cluster access here). Expected weak spots: the routing call
  now has three tools; in the JSON-in-text fallback the model is told to answer with JSON on every call, so the
  loop only finishes by a repeated call, the round cap, or a plain-text answer.
- Questions like "how much on ads in October" depend on the model summing `team_costs` rows (no category aggregate
  tool exists; adding one needs a new MCP tool, out of scope).
