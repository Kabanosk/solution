## Goal
`cfo smoke` / `python -m cfo.smoke`: one PASS/FAIL line per check, exit 1 on any FAIL (task T048).

## What was done
- `backend/cfo/smoke.py` (+ `__main__` guard, `python -m cfo.smoke`). `run_smoke(...)` takes every collaborator as an argument
  (httpx clients, toolbox, LLM factory, DB counter), so tests use fakes only. Checks:
  - `llm.models`: `GET {LLM_BASE_URL}/models` lists `LLM_MODEL` (FAIL names what is served).
  - `llm.tool_calling`: raw chat request with a `get_weather` tool must return `tool_calls`. HTTP 400 mentioning tools is a
    FAIL with the hint `--enable-auto-tool-choice --tool-call-parser=hermes`; a text answer is a FAIL too.
  - `llm.fallback`: the production `OpenAICompatLLM` forced onto the T041 JSON-in-text path must parse a call. WARN while
    native calling works (fallback unused), FAIL when native calling is down too.
  - `mcp.<server>.tools` / `.read`: `list_tools` contains the tool names the agent uses; one read each (`list_teams`,
    `org_chart`, `list_workstations`). Unset `MCP_*_URL` is a FAIL naming the variable; each MCP call has a 20 s timeout
    (daemon thread), so a hung server cannot hang the run.
  - `db.seeded`: `SELECT count(*) FROM transactions` > 0. `mlflow.reachable`: `GET {MLFLOW_TRACKING_URI}/health`, SKIP if unset.
- Reuse: `cfo.config.get_settings`, `cfo.run.get_run_settings` (MCP URLs; imported lazily so `--help` stays light),
  `cfo.llm.tls_verify_setting` (`LLM_VERIFY_TLS`), `McpToolBox`.
- `backend/cfo/agent/tools.py`: `McpToolBox.list_tools(server)` and `InProcessToolBox.list_tools(server)`. The sync/thread
  handling and session setup of `McpToolBox` were factored into `_run` / `_session` (behaviour of `call` unchanged).
- `deploy/cfo-entrypoint.sh`: `smoke)` case plus usage line. `docs/cluster-setup.md`: section 9.
- Not touched: agent graph, chat.py, API, deploy YAML.
