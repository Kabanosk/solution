# T049: Cost alert sentence always states the cost change and the metric change in EUR

- **Agent / model:** coder (Claude Fable 5.2)

## Goal
The cost-vs-metric alert (demo step 4) must say which cost changed, by how much (percent, EUR before to now), how
the metric moved and the cost per unit in EUR, also with the real Granite ([task](../tasks/T049-cost-alert-wording.md)).

## What was done
- `backend/cfo/agent/investigate.py`
  - Facts (`_facts`): `currency: "EUR"`, `cost_before_eur`, `cost_now_eur` (two decimals), all percents rounded to
    one decimal, `cost_per_unit_before` / `cost_per_unit_now` (two decimals), `cost_per_unit_name`, and
    `new_cost: true` when the cost rose from zero.
  - `what` is now the cost ("Cloud cost for the ordering app"). Before it was the per-unit noun ("cloud cost per
    online order"), which is the likely reason Granite led with the 45.63 % per-order change.
  - `INSTRUCTION`: lead with the cost change (percent, EUR to EUR), then the metric change, then the cost per unit;
    EUR next to every amount, never "units".
  - Guard `states_cost_change(text, facts)`: the LLM sentence is used only if it contains "EUR" or the euro sign and
    the rounded cost change as a number of its own ("50", "50.0", "50,0" match 50.0; "300.50", "150", "50.4" do
    not), or the word "new" for a new cost. Otherwise the deterministic `summary` is used.
- `backend/cfo/analysis/cost_metrics.py`: the deterministic sentence now carries the EUR amounts of the cost itself,
  so it has EUR even without line items or a per-unit cost:
  "Cloud cost for the ordering app rose 50.0% month over month (from EUR 200.00 to EUR 300.00) while online orders
  grew only 3.0%: Compute went from EUR 200.00 to EUR 300.00, cloud cost per online order from EUR 0.20 to EUR 0.29."
- `backend/tests/test_cost_alert_wording.py` (10 tests, no database: a stub gateway feeds the investigation graph).

## Deviations from the task text
- `cost_change_pct` stays in the facts as `None` for a new cost (next to `new_cost: true`) instead of being left
  out: `test_review_fixes_t044.py` asserts the `None` and that it is stored in the decision payload.
- The per-unit keys are `cost_per_unit_before` / `cost_per_unit_now` without an `_eur` suffix, because the
  protected `test_golden_path.py` reads `facts["cost_per_unit_now"]`. Its value went from four decimals to two.
- The guard also requires the currency (EUR or the euro sign), not only the percent. The task asked for the percent
  check; the "units" wording from the T028 re-measure would otherwise pass the guard.
