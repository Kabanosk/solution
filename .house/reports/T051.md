  `scout-guardrails-client` with a 720 h token, value not in git or here). The service stays running.

## Tested and did not work
- `tool-result` with `tool_input.flows: [regex check input]` as the task and Red Hat docs suggest: the rail ran
  (`rails_status` showed it) but never blocked anything, 0/5 poisoned results caught. Cause: the library flow reads
  `$user_message`, empty for tool messages. Fix: custom subflow `check tool result` in `rails.co` calling
  `detect_regex_pattern(source="input", text=$tool_message)`; 5/5 afterwards. The flow named `regex check input` must not
  be used there (a test guards it).
- First `user-input` prompt (policy list only, no examples): Granite complied with yes/no every time (no prose, so no
  need for `max_tokens` tricks beyond `max_tokens: 3`, `temperature: 0`) but over-blocked: UI-02 (pay an invoice, PL) and
  UI-03 (aggregate payroll) came back "yes" 3/3, "summarise payments for the CEO" and "average salary in the kitchen"
  too. Adding allowed topics plus 8 few-shot examples fixed it: 0 false positives in 100 calls. One NeMo call differed from
  my direct vLLM call for UI-03 in the first run, so measure through NeMo, not only against vLLM.
- `oc exec` into `scout-worker` to test the in-cluster URL from the real client pod was refused by the permission
  system (another workload); I tested from the NeMo pod instead, which has the same service-ca file. T052 should
  confirm the CA path from the Scout pod.

## Review round 1 (codex, `review-T051.md`: 3 MAJOR, 1 MINOR; all four were real and are fixed)

1. **Plaintext message logging (MAJOR).** Cause found in the pod source: `nemoguardrails/server/api.py` does
   `logging.basicConfig(level=logging.INFO)` and the action dispatcher plus the regex/Presidio actions log action
   parameters and results, i.e. the full checked text (reproduced: 6 hits for a test prompt in `oc logs`). No env var or
   `config.yaml` key controls it in this image. Fix: `deploy/openshift/guardrails/configs/quiet_logs.py` is mounted as
   `config.py` in all three configs; the server imports it when loading a config and it sets the root and `nemoguardrails`
   loggers to WARNING. Verified on the live pod after the full 23-prompt run (all three configs exercised): `oc logs` has
   0 hits for `IGNORE ALL`, `Ignore all`, `kowalski`, `Anna`, `4111`, `PL61`, `collector`, `evil`, `Zignoruj`, `Metro`,
   `salary`, `is_match`, `action_name`; only uvicorn access lines (23 POSTs, no content) and Presidio startup warnings remain.
   `docs/guardrails.md` has a "Logs" section with the verification command and the fallback (restrict `pods/log`) if a
   later image ignores `config.py`. A test checks every ConfigMap carries it.
2. **URL allow-list (MAJOR).** The old `\b` after the allowed domain let `example.com.evil.net` through. The lookahead now
   requires the host to end right after an allowed domain: `(?=[/:?#\s)]|$)`. Checked locally on 10 URLs and live with new
   prompts BO-06 (`https://example.com.evil.invalid/...`, blocked), BO-07 (`https://example.com@evil.invalid/...`,
   blocked) and BO-08 (allowed `svc.cluster.local` and `www.example.com` hosts, passes). Unit tests cover prefix, userinfo,
   `notexample.com`, `localhost.evil`, path-contains-domain and `svc.cluster.local.evil` bypasses plus allowed subdomains/ports.
3. **TLS (MAJOR).** `check_prompts.py` no longer has `--insecure`/`verify=False`: it refuses non-https URLs and always
   verifies certificate and host name (`--ca`, else system store). Docs: curl uses `--cacert`; from a pod the OpenShift
   service CA (`service-ca.crt`); from a laptop the ingress CA taken from ConfigMap `default-ingress-cert` in
   `openshift-config-managed` (readable with the project login here; verified with `curl --cacert`, `ssl_verify_result 0`,
   and by the final run below). Tests assert no `-k`/`--insecure`/`CERT_NONE` in docs or script.
4. **`activated_rails` (MINOR).** `has_activated_rails()` fails any response whose `guardrails_data.log.activated_rails` is
   missing or not a list (output shows `MISSING activated_rails`); unit-tested.
