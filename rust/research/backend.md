# Backend Rust migration evidence

Research date: 2026-11-21. This is a feasibility and parity inventory, not a claim that these modules have been ported or tested. Production sources remain unchanged. `backend-inventory.json` is generated by Python AST parsing without importing or executing application modules.

## Measured scope and entry points

The production backend contains **123 Python modules, 22,256 source lines, 36 declared application routes and four mock-bank routes**. Tests are excluded from these source counts. The inventory records every module, import, top-level definition, literal route/prefix and SQL asset. FastAPI-generated documentation routes and middleware restrictions are additional behavior; the route list alone is not an authorization contract.

`deploy/cfo-entrypoint.sh` dispatches API, worker, mock bank, three MCP services, seed, migration, data generation and data load. Forecast training/tuning/evaluation/comparison and usage reporting have separate Python module entry points. Rewriting only FastAPI handlers does not replace the backend application.

## Replacement candidates and traps

| Current dependency / responsibility | Rust candidate / approach | Fit and evidence |
| --- | --- | --- |
| FastAPI, Starlette, Uvicorn | Axum + Tokio + Tower | Good server fit. Axum supports routing, extractors, middleware and shared state. Validation errors, redirects, headers, OpenAPI generation, method handling and streaming cancellation need explicit parity implementations. [Axum documentation](https://docs.rs/axum/latest/axum/) |
| psycopg, PostgreSQL JSONB, transactions, notifications | SQLx PostgreSQL or tokio-postgres | Good database protocol fit; preserve existing SQL and transactions. SQLx requires runtime/TLS features; tokio-postgres requires driving its connection future. Select one driver before defining repository interfaces. [SQLx](https://docs.rs/sqlx/latest/sqlx/), [tokio-postgres](https://docs.rs/tokio-postgres/latest/tokio_postgres/) |
| Pydantic models/settings, Decimal | Serde plus explicit validators/config loader; rust_decimal | Partial semantic fit. Rust Decimal has finite 96-bit storage; Python Decimal is context driven. Match string serialization, trailing zeros and field defaults. Python rounding is generally half-even; KSeF explicitly uses HALF_UP in several functions. [rust_decimal](https://docs.rs/rust_decimal/latest/rust_decimal/) |
| httpx / OpenAI-compatible LLM client | reqwest, typed request/response models | Good HTTP fit. Reuse a client; configure redirects, timeouts, proxy/TLS behavior, SSE/NDJSON, tool calling and usage recording explicitly. Do not replace LLM output with static answers. [reqwest](https://docs.rs/reqwest/latest/reqwest/) |
| slack-bolt / Slack Web API / Socket Mode | slack-morphism plus tenant-aware supervisor | Candidate supports Web API, Block Kit, OAuth and Socket Mode. Preserve installation generation checks, envelope acknowledgments, dedupe, reconnect behavior, directory synchronization and DM-reply fallback. [slack-morphism](https://docs.rs/slack-morphism/latest/slack_morphism/), [Slack Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/) |
| Google OAuth / Gmail client | OAuth authorization-code library plus reqwest Gmail REST client | Partial integration fit; retain the existing owner-bound, single-use OAuth state and encrypted per-connection refresh tokens. Preserve required label filtering, MIME/base64url attachments, expired/revoked credential transitions and pagination. Gmail API query dates use PST unless expressed as epoch seconds. [Google web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Gmail filtering](https://developers.google.com/workspace/gmail/api/guides/filtering) |
| cryptography.Fernet | fernet plus hmac/sha2/base64 | Interoperable format candidate. Match `derive_key` exactly: HMAC-SHA256(master UTF-8, `scout-connection/v1|<organization_id>|<connection_id>`), URL-safe base64. Do not substitute another ciphertext format for stored rows. [fernet](https://docs.rs/fernet/latest/fernet/) |
| KSeF: SignXML XAdES, X.509, AES/RSA | XML security implementation + certificate/crypto crates + reqwest | **High-risk, not a verified drop-in.** Existing code signs XAdES-BES with enveloped RSA-SHA256 and C14N 1.1, then wraps session AES keys and encrypts invoice data. Generic RSA signing alone is insufficient. `xml-sec` advertises XMLDSig/C14N, but complete compatibility with this XAdES profile has not been demonstrated. Require recorded signatures and a real KSeF TEST login/send/read round trip. [KSeF authentication](https://github.com/CIRFMF/ksef-api/blob/main/uwierzytelnianie.md), [xml-sec](https://docs.rs/xml-sec/latest/xml_sec/) |
| pypdf text extraction | pdf-extract or another parser, preserving current fallback | Partial output fit. Extraction order and whitespace affect the exact LLM input. Current `scout/documents.py` falls back to Latin-1 PDF literal strings after any parser failure/empty extraction; non-PDF input must be valid UTF-8 or return empty. Record real PDFs and malformed fixtures. [pdf-extract](https://docs.rs/pdf-extract/latest/pdf_extract/) |
| Python MCP SDK / FastMCP | official rmcp Rust SDK | Good protocol candidate, not automatic tool-schema parity. Current `cfo.mcp_servers.__main__` explicitly rejects non-stdio transport despite older dispatcher help advertising HTTP. Preserve that effective restriction and all tool access/audit controls. [Official Rust MCP SDK](https://github.com/modelcontextprotocol/rust-sdk) |
| LangGraph / PostgreSQL checkpointer | Explicit durable Rust state machine | No verified compatible Rust checkpoint implementation selected. Preserve approval interrupts and resume behavior, including existing interrupted tasks/checkpoint rows. Source: `scout/loops/liquidity.py`, `scout/db.py`, `cfo/db/migrate.py`. This is a migration boundary, not a reason to silently discard pending approvals. |
| pandas / NumPy / scikit-learn | Explicit typed feature/schedule/band algorithms, potentially ndarray | Partial fit. Port current formulas before optimizing: date offsets/month ends, missing days, median, quantiles, standard deviation degrees of freedom, stable ordering, float conversions, cumulative rounding and fixed-cost schedule inference. No library choice alone proves numerical equivalence. Sources: `cfo/forecast/{features,schedule,band,folds,evaluate,model}.py`. |
| XGBoost training/inference | xgb bindings to matching libxgboost | **Native-dependency candidate, not pure Rust.** Official C API supports bindings; model JSON carries trees/objective. Rust `xgb` links a native library; current docs.rs page reports failed 3.4.2 docs builds and warns about non-semver releases/platform dependencies. Pin and build-test the chosen version. Training, SHAP contributions and importance need the same feature order/parameters/library, not an approximation. [XGBoost C API](https://xgboost.readthedocs.io/en/stable/c.html), [model IO](https://xgboost.readthedocs.io/en/stable/tutorials/saving_model.html), [xgb crate](https://docs.rs/crate/xgb/latest) |
| MLflow optional tracking/registry | REST client preserving run/model/artifact semantics | Feasible HTTP boundary. Runs/params/metrics/registry/artifacts must retain current behavior, authentication and TLS configuration. Current model loads a booster plus metadata sidecar; retrieving only the booster loses schedule/band/level state. [MLflow REST API](https://mlflow.org/docs/latest/api_reference/rest-api.html) |
| NeMo Guardrails service | Keep external service, Rust HTTP client | Good language-independent boundary. OpenShift AI documents `/v1/guardrail/checks`; do not substitute a newer NVIDIA endpoint from unrelated deployment docs. Preserve fail-open unavailable status, blocked/success/error parsing, warm-up throttling, audit, strike counters, PII masking and organization switch. [Red Hat Guardrails guide](https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/enabling_ai_safety_with_guardrails/index), source `scout/guardrails.py`. |
| Optuna, matplotlib, Jupyter tooling | Unselected | No researched drop-in pure-Rust replacement for the existing Optuna sampler/pruner and notebook execution contract. These are optional training/development entry points, but are included by the user's whole-application request unless scope changes explicitly. |

CPU-bound PDF/model work must not block Tokio executor threads. Tokio documents that started `spawn_blocking` jobs cannot be aborted; bound concurrency and plan shutdown/lease renewal independently. [Tokio blocking tasks](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html)

## Security and durable-state parity requirements from local code

- `cfo/api/auth.py`: only `GET`/`HEAD /healthz` are unauthenticated. Every other route, stream and docs request requires a valid DB session and `X-Scout-Organization`; duplicate Authorization/organization headers are rejected. DB auth failure is 503, invalid identity is 401, blocked legacy mutation/demo endpoints are 403. A static API token is not a substitute for membership identity.
- `cfo/tenancy.py`: schema registration is validated against organization UUID; a request or job must carry a verified immutable tenant. There is no implicit public tenant. Pool checkout/release must not leak a prior request's `search_path`.
- `scout/config.py`: a new organization must not inherit global Slack/mail/bank/file credentials, seeded identities or demo mode. Global provider app registrations and connection master secret are different from tenant credentials.
- `scout/jobs.py`: preserve unique dedupe, `FOR UPDATE SKIP LOCKED` claims, attempt fencing on renew/done/fail, default 900-second lease, 180-second DM reply lease, final-attempt reaping, retries and backoff. Tokio task spawning does not replace this durable queue.
- `scout/policy.py`: exact rule precedence and boundary comparisons matter. Routine payments precede inflow checks; new suppliers below 1% are NOTIFY; exactly 1% and 5% are distinct boundary cases. Python casefold is not equivalent to simple Rust lowercase for all Unicode.
- `scout/onboarding/http.py` restricts provider base URLs, disallows redirects and uses short timeouts. `onboarding/service.py` adds a 20-second KSeF wall budget. Rust HTTP defaults must not weaken those constraints.
- `cfo/forecast/model.py`: `components` is the current default feature set; model state includes fixed schedules, shutdown days, level values, empirical band metadata and registry metadata. Forecast ownership and artifact paths are tenant-specific.

## Recommended independent first units

Record pure, deterministic contracts first: money/policy classification, guardrail parsing/masking, KSeF NIP/FA(3) arithmetic/parsing, schedule/calendar math, then database repositories and authenticated HTTP routes. Keep integration operations on isolated test services while recording effects. Do not mark whole-app replay complete from health/auth-only cases. Require DB state dumps, queued-job/approval transitions, connector side effects and representative UI-to-worker flows before fallback is removed.

Unresolved blockers for claiming a pure Rust application: complete XAdES interoperability; existing LangGraph checkpoint migration; native XGBoost acceptance/build parity; Optuna/notebook scope; a recorded DB/provider integration corpus. These are explicit gaps, not implemented substitutes.
