# Native financial read service

`rust/finance-api` ports the deployed read-service path for `/v1/kpis`, `/v1/forecast/liquidity`, `/v1/costs/by-team` and `/v1/cost-metrics`, including `cfo.analysis.cost_metrics` and response DTO semantics. The public interface is the requested `FinanceApi`/`FinanceOptions`; API errors use the already integrated Scout envelope. Original Python production sources remain unchanged.

Forecasts use the verified tenant's artifact directory, matching custom FORECAST_MODEL_PATH basenames. Missing artifacts train natively with the original defaults, including rolling-fold measured bands, then save portable booster/sidecar files. Models cache under a lock by path and mtime, refresh levels per request and run CPU work off the async executor. Source MLflow registry lookup returns None whenever a tenant is bound; this authenticated service follows that boundary. Optional unbound/operator MLflow transport remains a separate unit.

Financial JSON preserves source field order, EUR amount/currency objects, half-up cent/percentage formatting, Decimal precision-28 division, complete-month averages, undocumented invoice counts, nullable missing Scout tables and last-point anomaly counts. Forecast weekly samples retain the trough; bands and gaps describe every day. Cost ranges preserve partial-month inclusion, unassigned company costs, unlinked invoices, refunds, zero teams, stable ordering and exact validation messages. Cost analyses preserve the three pair order, consecutive-month checks, zero-denominator cases, driver precedence/invoice fallback/tie sorting and original narrative templates.

Evidence is direct source characterization, not a separate rust-anything API unit gate. Thirty complete original handler scenarios match against a rich, dedicated local database tenant, with both default/configured buffers, 7/8/90/365-day forecast windows, cost ranges, errors, KPIs and all cost pairs. A separate Rust corpus replays 295 original cost-metric cases around the 20%/10% thresholds, new costs, zero metrics, month gaps, duplicate bill lines, invoice fallback, Decimal rounding and unusual detail labels. The DB integration test verifies empty-data errors, default date range, explicit inversion, tenant-only cold-start artifact creation and repeated/concurrent requests without retraining. The service reuses the 1,102-, 346- and 389-case gated forecast implementations. Root authenticated HTTP replay remains the integration proof.

Reproduce with the checked-in `finance-api-reference` scripts and `finance-api/examples/characterize.rs`; source import guards validate hashes from `finance-api/source-provenance.json`. The financial fixture is separate from the root HTTP fixture and contains no production credentials. `cargo test`, format and strict clippy checks are recorded alongside the service. Native deployment packages libxgboost 3.4.1 and the forecast model's Intel sorting notice.
