# Native deployed forecast kernels

Implemented `rust/forecast` / `scout-forecast`, generated and checked using rust-anything against a hermetic source bundle. Native entry points are `scout_forecast::port::native`; `port::evaluate` is the JSON characterization boundary.

The deployed kernels covered are calendar features and feature-set ordering, German public holidays, due-day inference/clipping, shutdown inference including trailing-run distinction, strict-before-origin recent open-day levels, level/applied baseline, daily flow/features, periodic fixed-cost schedule inference including partial-month posted-payment replacement, schedule amounts/totals and legacy/empirical band offsets. No training, tuning, fold generation or fit_band fitting is ported; those are retained Python development utilities under the user's clarified scope. Database readers and monthly-cost aggregation remain separate integration work.

Verification (2026-11-21): **1,102/1,102 recorded cases match**, including **891 structured cases**. One native Rust test replays the full corpus; all **12 rust-anything gate checks pass**, including fmt, clippy with warnings denied, build/API/behavior, unsafe/panic checks and source size (1,084 Rust code lines / 563 Python source lines). Raw result is `forecast/gate-report.json`.

Float recordings compare IEEE754 bits, with explicit NaN markers, rather than decimal strings or widened tolerances. The native routines return ordinary numeric values; only the characterization boundary emits bit markers. Cases cover sorted/unsorted histories, calendar/leap/holiday boundaries, sparse/trailing shutdowns, amount/category exclusions, mixed positive/negative refunds, empty history, level windows, forecast-day leakage prevention, schedule period/partial-month matching, integer-versus-float result columns and signed zero.

A discovered compatibility trap matters: installed pandas **3.1.1** uses NumPy add.reduceat for monotonic group IDs and compensated aggregation for its fallback; rolling means maintain separate addition/removal compensation. The exact operation order is preserved, matching the recorded low-bit differences without tolerances. Evidence: [pandas groupby operation source](https://github.com/pandas-dev/pandas/blob/v3.1.1/pandas/core/groupby/ops.py), [rolling kernels](https://github.com/pandas-dev/pandas/blob/v3.1.1/pandas/_libs/window/aggregations.pyx), [NumPy 2.5.5 pairwise reduction](https://github.com/numpy/numpy/blob/v2.5.5/numpy/_core/src/umath/loops_utils.h.src).

`forecast-reference/provenance.json` pins source files and private snapshots; every reference import validates those hashes. Snapshot pure function bodies are retained from the original; DB readers and training-only fit_band are excluded. The JSON adapter reconstructs hashable shutdown tuples before calling the typed Python function. Corpus inputs are regenerated by `forecast/generate-stress.py`; original results are recorded by rust-anything, never generated by the Rust implementation.

This proves the characterized pure kernels, not a complete deployed forecasting feature. Remaining work includes XGBoost model loading/state/SHAP/importance, MLflow model resolution, runtime tenant-local training used by the chat bridge, liquidity analysis/recommendations, API/worker wiring and end-to-end forecasting recordings. In particular, `scout/forecast_bridge.py` currently trains on each authenticated tenant's rows at runtime inside a read-only transaction; a global model must never silently replace that behavior.

Production integration uses the plain `forecast-kernel` crate, whose `[lib].path` compiles the exact `forecast/src/port/native.rs` tested through the characterization bridge. The shared implementation also exports `pandas_sum` for downstream model aggregation. The final gate was rerun after adding this helper; the 1,102-case corpus remains unchanged.
