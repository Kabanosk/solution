# Deployed forecast model: artifact and inference unit

The native model implements the artifact-loaded portion of `cfo/forecast/model.py` and the pure balance-forecast kernels. No Python production source changed. The source snapshots in `forecast-model-reference/contract` validate original source and snapshot hashes on import. Existing-model inference is distinct from runtime tenant training, MLflow artifact resolution and liquidity review orchestration; those remain open.

The production crate is `forecast-model-native`. Its `[lib].path` points at the actual shared implementation `forecast-model/src/port/native.rs`; the characterization crate adds only a JSON/PyO3 boundary. Feature kernels are also shared through the plain `forecast-kernel` crate. `forecast-model/source-provenance.json` records paths and hashes. This avoids duplicate PyInit symbols and separate production/recording implementations.

The implementation loads actual XGBoost JSON and `.meta.json`, including legacy missing metadata defaults, feature sets and exact feature ordering. It refreshes level baselines and fixed schedules from transaction history; implements predictions, measured/legacy bands, normalized feature gains, SHAP contribution frames, top drivers, partner tranche schedules, last known balance, future net/balance curves and lowest balance. Native `libxgboost` 3.4.1 is accessed through the safe `xgb` wrapper, with no Python subprocess. Native-library deployment must package the matching library and configure `XGBOOST_LIB_PATH`. [XGBoost C API](https://xgboost.readthedocs.io/en/stable/dev/c__api_8h.html), [xgb 3.4.1](https://docs.rs/xgb/3.4.1/xgb/).

The 346 saved cases include 135 structured scenarios over four genuinely trained synthetic model artifacts and a legacy sidecar: every feature set, metadata, 0/1/multiple dates, refreshed levels/schedules, scheduled payments, negative balances, asymmetric uncertainty, SHAP and empty/invalid inputs. Floating results cross the characterization boundary as IEEE754 bit strings; every case matches exactly, with no widened tolerances. The rust-anything gate passes all 12 checks. Rust tests replay the full model corpus and a separate 1,024-case deterministic sort corpus.

A parity-sensitive detail is pandas' descending order of tied feature scores. The source NumPy wheel dispatches to the AVX2 four-lane Intel sorting network; stable sorting gives different visible drivers. The Rust implementation translates the actual scalar lane/merge operations, including retaining each lane on equal keys and reversing before/after the ascending argsort. It therefore reproduces this reference behavior on CPUs with different SIMD support. BSD-3-Clause copyright, conditions and disclaimer are retained in `forecast-model/THIRD-PARTY-NOTICES` and must accompany binary distribution. [NumPy dispatch source](https://github.com/numpy/numpy/blob/v2.5.5/numpy/_core/src/npysort/x86_simd_argsort.dispatch.cpp), [pinned Intel network](https://github.com/intel/x86-simd-sort/blob/fa944efbea1a33426b3f8a9a21e23794ab8aa300/src/xss-network-keyvaluesort.hpp), [register network](https://github.com/intel/x86-simd-sort/blob/fa944efbea1a33426b3f8a9a21e23794ab8aa300/src/xss-reg-networks.hpp).

Open required runtime units: source-compatible dynamic training/backtesting/measured bands; model retrieval/logging through MLflow when configured; liquidity gap/surplus proposals and narrative facts; forecast/hiring bridge database and task effects. The existing artifact fixtures do not prove those behaviors.
