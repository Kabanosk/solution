# Deployed forecast runtime training

`forecast-training-native` compiles the same real algorithm files as the `forecast-training` rust-anything bridge. It receives tenant transactions and returns an actual freshly trained `ForecastModel` plus learning curves. It does not consult a global model or launch Python. The default API is `train(transactions, &TrainingOptions::default())`; Scout's request bridge sets `band=false` explicitly, while API cold-start defaults retain band measurement.

Ported source algorithms: daily training tables and category exclusions, lagged recent levels, trailing shutdown flags, component closed-day filtering; automatic components → level_baseline → calendar fallback and explicit 28-open-day validation; chronological 60-day holdout with calendar inference restricted to seen bookings and frozen holdout levels; native XGBoost fits and training/holdout learning curves; exact daily/naive/total holdout metrics; per-model schedule, levels, baseline metadata; rolling-origin measured bands and stored asymmetric growth/anchors. Python CLI/notebook orchestration remains development tooling.

The source bundle snapshots actual training functions and model class without remote MLflow loading; `reference_band.py` is the original band implementation. Imports validate live source/snapshot SHA256 hashes. Source records were taken before implementing training and then extended with untouched original boundary cases. 389 cases include 178 structured cases: every feature set, 1/6/7/27/28/34/35/60/90-day boundary histories, default 326-tree component parameters, 20/60-day holdouts, duplicate/reordered exclusions, 310/365-day histories, genuine rolling folds, band slopes/asymmetry and metadata. All outputs, curves and predictions match exact IEEE754 bit markers. No tolerance or known difference was introduced. Gate and test evidence lives in `forecast-training/gate-report.json`.

Native libxgboost 3.4.1 performs every fit. The Rust wrapper's default constructor explicitly sets base_score=0.5; XGBoost interprets explicit intercept as disabling automatic estimation. The implementation instead initializes a zero-tree learner generated by the official 3.4.1 serializer, sets only the actual feature count and then trains from scratch. This contains no fitted state or tenant data and retains boost_from_average=1, matching the source estimator. [XGBoost learner initialization](https://github.com/dmlc/xgboost/blob/v3.4.1/src/learner.cc), [intercept parameters](https://xgboost.readthedocs.io/en/stable/parameter.html).

Learning-curve evaluation preserves XGBoost's f32 residual/square operations and f64 sequential aggregation. Source scalar metrics retain NumPy/pandas reductions. The fitted-band slope uses a scalar centered least-squares formula; the complete source-visible result is rounded to four decimals as in Python and is compared exactly, including all stored anchors. The corpus includes clamp regions and real trained fold errors. [Native metric source](https://github.com/dmlc/xgboost/blob/v3.4.1/src/metric/elementwise_metric.cu).

Integration requirements: package matching libxgboost with `XGBOOST_LIB_PATH`; retain Intel sorting notice from forecast-model; use only scoped tenant database rows; move CPU fits off the async executor. MLflow remote artifact resolution/logging and liquidity review/proposal/database task effects remain separate open work. Optional arbitrary XGBoost callable Python objectives/metrics are not a Rust runtime interface; the application supplies ordinary JSON params.
