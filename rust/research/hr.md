# Native HR and audit database context

The plain `hr` crate compiles the shared algorithm in `hr-characterization/src/port/native.rs`. Production uses only verified tenant database storage; the fake SQL-store adapter is compiled only by the characterization feature. Shared domain::People methods preserve employee lookup, explicit Slack-ID override/database fallback, source names and role codes, inclusive vacations, cycle-safe manager chains and first-available routing. EmployeeMap is insertion ordered, retaining source duplicate-Slack-ID behavior. Legacy link_slack preserves registered members and writes configured links transactionally.

411 recorded cases (200 structured) characterize the original HR class through a read-only SQL adapter before porting. They cover absent employees, explicit vs stored Slack IDs, names, source marketing→waitstaff role mapping, whitespace-only name errors, unknown/empty identifiers, vacation endpoints and manager cycles. Source and snapshots validate hashes on import. Gate evidence is stored in hr-characterization/gate-report.json.

A real isolated PostgreSQL test created two unique tenant schemas, applied the original company/Scout schema, and verified overlapping vacations, manager-cycle termination, explicit Slack map precedence, registered-link preservation and tenant isolation. The same test exercised concrete Audit persistence, ALLOW/DENY checks, one-person payroll denial, two-person MASK aggregation, per-hidden-row audit effects and 500-Unicode-codepoint resource truncation. Both schemas were dropped afterward. Source analysis does not infer identities from display names or relax salary access.
