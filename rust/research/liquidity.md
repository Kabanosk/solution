# Native liquidity reviews and proposals

`liquidity-native` compiles the same real Rust implementation as the `liquidity` characterization bridge. It ports the deployed calculations from `cfo.forecast.liquidity`: worst-month fixed-cost buffers, normalization and aggregation of extra inflows/outflows, forecast overlays, contiguous below-buffer gaps, recovery dates, full-month surplus opportunities, credit sizing/reserve/lead/tail periods, investment amounts/periods, model feature phrases and monthly SHAP narratives. Proposals call the already gated native policy classifier, preserve CEO overrides and expose the exact METRIC payload/approval flag.

Money uses the shared precision-28 Decimal module; cents and narrative integer EUR formatting retain the original HALF_EVEN rounding, positive/negative signs, scale and negative zero. Model predictions and contribution order reuse the gated native model. Caller orchestration supplies a verified tenant's transactions/model explicitly; DB fetching and default artifact selection are caller responsibilities, not a hidden global fallback.

352 recorded original cases (141 structured) match exactly, including IEEE754 bit strings, Decimal strings and complete narrative/payload text. The corpus covers every feature set, 7/90/365-day reviews, what-if inflow/outflow/tuple/dictionary forms, same-day aggregation, invalid horizons, threshold equality, repeated troughs, recovery/open gaps, multiple reordered gaps, reserves, surplus planning, no fixed-cost history, policy overrides and rounding/negative-zero/scientific-scale boundaries. All 12 rust-anything gate checks pass; Rust tests replay the same untouched corpus. Source/snapshot hashes are checked on original adapter import. Native source hashes and shared crate paths are recorded in `liquidity/source-provenance.json`.

No original Python production source changed, and deployed calculations do not launch Python. Native libxgboost 3.4.1 and the model's Intel sorting notice remain packaging requirements. Forecast/hiring bridge effects and worker loops are separate next units; this unit does not claim those are integrated.
